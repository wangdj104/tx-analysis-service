# 平台功能与场景回归审查（2026-09-22）

## 验证口径

本次按患者、家属、医生、管理员四类角色，检查英文与中文正式应用、静态演示和部署配置。发现的问题已加入相应回归测试。审查不是“所有外部服务已经接通”或“任何输入都不会出错”的保证。

- **业务验证**：JUnit、Mockito 与 H2 MySQL 模式，使用隔离合成数据，覆盖真实服务方法、SQL、权限和失败分支；不改动生产患者记录。
- **界面验证**：本地双语应用配合合成 API 的独立无头浏览器，检查页面、子页签、角色入口、问诊输入与窄屏布局；不把它称为生产端到端测试。
- **生产验证**：数据库结构只读核对、明确范围的补表、发布后服务健康检查及双语静态资源可用性。未用真实患者发送测试医嘱、急救、Webhook 或短信。

## 使用入口说明

- **医生收件箱**：医生工作台或顶栏的问诊入口 → 健康照护全流程 → 远程问诊。无需先从全局列表选中患者；只能打开本人参与的会话。
- **医生预约**：医生工作台的预约入口 → 健康照护全流程 → 运营管理 → 本人预约。仅预约不授予完整病历权限。
- **患者发起问诊**：选择本人患者 → 远程问诊 → 选择医生、方式、症状 → 开始问诊 → 在下方多行输入框发送文字。附件与家属邀请单独操作。
- **中文文字导入**：透析记录 → 粘贴文本导入 → 按日期分组 → 解析预览 → 确认。改动文本或切换患者后必须重新预览。

## 不能用“测试通过”替代的上线验收

1. 正式服务器目前使用 HTTP/IP 地址。音视频、定位及部分浏览器通知需要 HTTPS、安全上下文、设备权限；公网跨网络通话可能还需要 TURN。文字聊天不依赖摄像头权限。
2. 企业微信/钉钉、AI、OCR 需要有效渠道或供应商凭据。未向真实家庭发送测试通知、未上传真实医疗资料。
3. 应用内备份不包含问诊/全流程/医生工作台/账号与授权的全部表，不含非内嵌附件；完整灾备需数据库和附件存储备份。
4. 静态 demo 使用虚构数据，是交互展示，不连接生产数据库，不能据此证明线上实时通信可用。
5. 全新 Docker 环境与真实摄像头设备验收与已运行服务器发布验收分开记录，不能只靠配置审查宣称它们已实测。
