# 交互式静态演示

在浏览器中打开 [index.html](index.html)，或访问[中文在线演示](https://wangdj104.github.io/tx-analysis-service/cn/)。演示版无需账号、应用服务或数据库，使用虚构数据，与完整 Vue 应用相互独立。

演示版可切换医生、患者、家属、护理人员和管理员身份，并按照正式平台的菜单与流程边界呈现：患者分配和医生复核；照护计划与每日任务；指标、用药、医疗记录、透析和干体重；营养和健康分析；复诊与家庭交接；通知渠道；用户、角色、菜单、审计、自动分析和按范围导出。照护计划输入仅保留在当前标签页，刷新或重置后恢复；既有品牌与外观偏好使用独立的浏览器存储。

页面控件会产生可见的本地状态变化并写入演示审计事件。由于静态版没有后端，文件识别、AI 分析、渠道发送和服务端定时任务均为安全模拟；内容安全策略会阻止网络连接。演示复现真实产品的操作流程和复核门禁，但不声称执行了真实临床处理。

## 照护计划协作演示路径

使用虚构患者 **张爱华**（患者 1），此场景分别预置家属和护理授权。护理人员有独立受限跟进队列；只有护理分配并不足以访问。身份切换用于呈现同一虚构团队，并非安全身份认证。

1. 医生 → **照护计划** → **新建协作草稿**。精简演示编辑器提供两个一次性事项，分别由患者账号和家属账号负责。核对带明确偏移的 ISO 8601 截止时间后保存；草稿仅医生可见。
2. 医生 → **核对并发布**，核对内容、期限、接收范围并勾选发布确认。
3. 患者 → **照护计划**（今日任务也有此分组）→ **提交执行回执**。默认 ASSISTED，选择 SELF 只表示账号声明，并非患者身份认证。事项变为 **SUBMITTED**，仍需医生复核。
4. 家属 → **照护计划** → 提交另一个回执。家属、护理回执始终为 **ASSISTED**。待执行事项可通过 **说明困难** 进入 **NEEDS_HELP**。
5. 护理 → **照护计划跟进** → **记录跟进**。“已联系、等待补充、记录提醒医生”仅生成管理事件，不发布临床说明、不确认回执、不关闭计划。
6. 医生 → **退回补充** 并说明原因。再切换患者或家属提交新回执，首次提交和原时刻仍保留。医生逐项 **确认已复核** 后，才可 **关闭计划**。
7. 关闭前可 **新建修订草稿** → 编辑 → **核对并发布**。发布弹窗显示原内容、新内容及受影响事项 ID。旧未终结事项变为 SUPERSEDED，已确认历史保持 CONFIRMED；所有新事项从 OPEN 开始，不继承完成状态。
8. 展开回执及版本历史，最后 **重置演示**。照护计划输入及打开的弹窗字段会清空；刷新也恢复协作状态。切换身份或患者会丢弃尚未提交的弹窗输入。

此功能仅演示虚构协作。通知始终标注“仅演示结果”，内容安全策略阻止网络连接。不新增真实患者数据、临床建议、剂量、新上传、真实记录引用、后端持久化、凭据或 webhook 发送。历史内部计划保持独立，不会自动发布。领域模型校验每版本 1–50 个事项，精简演示编辑器固定展示两个。时间须带明确偏移，支持毫秒精度；正式数据库精度及并发合同另行验收。

## 使用 GitHub Pages 发布

仓库已包含 [GitHub Pages 工作流](../../.github/workflows/demo-pages.yml)。

1. 将项目推送到目标 GitHub 仓库。
2. 打开 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
3. 运行 **Actions → Publish static demo → Run workflow**。之后 `main` 分支下 `demo/` 或 `cn/demo/` 的变更会自动部署。
4. 英文版发布在 Pages 根路径，中文版发布在 `/cn/`。

发布内容仅包括静态页面、脚本、样式和演示图片，不会上传后端配置、SQL 文件、测试及仓库中的其他内容。

GitHub 参考文档：[通过自定义工作流使用 GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 验证

```bash
node --test demo/tests/*.test.mjs cn/demo/tests/*.test.mjs
node --check demo/app.js
node --check demo/model.js
node --check cn/demo/app.js
node --check cn/demo/model.js
```

浏览器验收时，请切换五种身份和不同患者；通过或驳回一项复核；新增照护计划；完成用药任务并核对库存；新增血压读数并核对表格、图表和任务状态；执行一个模块操作并在审计日志中核对；切换演示用户状态；打开档案；导出 CSV；最后重置演示。

`assets/` 下的图片来自项目自有资源，以确保演示版可以独立部署。产品标志或插图更新时，请同步更新对应的演示资源。

可选真实浏览器验收（需要已安装 Playwright，且环境允许启动 Chromium）：

```bash
node cn/demo/tests/carePlanCollaboration.browser.mjs
```

浏览器脚本覆盖双语版 1440px、390px 场景，将合成截图写入 `/tmp/care-plan-demo-qa`（可用 `DEMO_QA_OUTPUT` 指定目录）。它独立于不需要新依赖的 Node 测试。实施环境禁止创建套接字，Chromium 在打开页面前退出，因此未获得真实浏览器截图或通过结果；静态演示验证也不等于后端端到端验收。
